     تحديث — حل مشكلة Overhead بنظام Compression Flag
              التاريخ: 2026-05-19
══════════════════════════════════════════════════════════════

────────────────────────────────────────────────────────────
8. ملف: js/stage3_hide/embedding.js  (تحديث v2)
   الأسطر المعدّلة: 110 – 130
   الوظيفة: حل مشكلة overhead الضغط عبر نظام Flag ذكي.

   المبدأ: الـ flag يُضاف فقط عند نجاح الضغط.
   إذا الضغط سبب overhead → لا يُضاف أي flag (صفر overhead).

   الآلية:
   1. بناء الحمولة الخام: buildPayload() → payloadBytes
   2. محاولة الضغط: doStreamCompress(payloadBytes) → compressedBytes
   3. مقارنة الأحجام:
      - إذا compressedBytes.length < payloadBytes.length:
        → الضغط مفيد → [0xFE] + compressedBytes
      - إذا compressedBytes.length >= payloadBytes.length:
        → الضغط يسبب overhead → payloadBytes كما هي (بدون أي flag)
   4. النتيجة finalPayload تُحوّل إلى binary للتضمين.

   الحالة 1 — نص صغير (الضغط يسبب overhead):
   ┌────────────────────────────┐
   │ Raw Payload (no flag)      │
   │ (original bytes as-is)     │
   └────────────────────────────┘
   → صفر overhead — ولا بايت إضافي

   الحالة 2 — نص كبير (الضغط مفيد):
   ┌──────────┬────────────────────────────┐
   │ 0xFE     │ Compressed Payload         │
   │ (1 byte) │ (Brotli Stream output)     │
   └──────────┴────────────────────────────┘
   → 1 بايت flag + بيانات مضغوطة (أصغر من الأصل)

   لماذا 0xFE؟
   البايت 0xFE لا يظهر أبداً كأول بايت في ترميز UTF-8.
   الحمولة الخام تبدأ دائماً ببايت UTF-8 صالح (0x00-0x7F
   أو 0xC2-0xF4)، لذا 0xFE علامة حتمية وآمنة.
────────────────────────────────────────────────────────────

9. ملف: js/stage3_hide/extraction.js  (تحديث v2)
   الأسطر المعدّلة: 101 – 116
   الوظيفة: فحص وجود الـ flag وفك الضغط بناءً عليه.

   الآلية:
   1. استخراج البايتات: binaryToBytes(recoveredBinary) → recoveredPayload
   2. فحص أول بايت: recoveredPayload[0]
   3. تحديد المسار:
      - إذا أول بايت === 0xFE:
        → الحمولة مضغوطة → شيل الـ flag + فك الضغط
        → doStreamDecompress(recoveredPayload.subarray(1))
      - إذا أول بايت !== 0xFE:
        → الحمولة خام — ما فيها flag أصلاً
        → استخدام recoveredPayload مباشرة بدون أي تعديل
   4. تمرير النتيجة إلى parsePayload() لاستخراج النص + التلميح.
