Hidden Message Extraction Engine Architecture

This technical reference details the architecture of the zero-key multi-scheme steganography extraction engine located at js/features/stego-analysis/extract/.

Engine Architecture

  • carriers.js — Canonical frozen registry of invisible & evasive Unicode code points.
  • profile.js — Code point iteration, statistical metrics, gap analysis, and Arabic/Emoji orthographic legitimacy classification.
  • schemes/ — Extensible steganographic scheme registry (stegnolines, unicodeTags, variationSel, binary, baseN, positional).
  • decapsulate.js — Multi-layer decapsulated payload ladder (Base64/Hex -> gzip/deflate -> XOR -> entropy analysis).
  • sanitize.js — Strips suspect carriers while preserving legitimate orthographic joiners.
  • analyze.js — Main orchestrator scoring candidate hypotheses and performing prompt-injection & nested payload checks.
  • analyze.worker.js — ES module Web Worker for async background execution.

Candidate Shape

{
  schemeId: string,
  label: string,
  bytes: Uint8Array,
  text: string,
  confidence: number, // 0 to 100
  notes: string,
  decapsulation: DecapsulationResult,
  isPromptInjection: boolean,
  hasNestedPayload: boolean
}

Adding a New Scheme

To add a new steganographic scheme, export an object implementing the scheme contract in schemes/:

export const myNewScheme = {
  id: 'myScheme',
  label: 'Custom Scheme',
  canApply(profile) { return profile.suspectCarrierCount > 0; },
  decode(carrierSeq, profile) { return [ /* Candidates */ ]; }
};
